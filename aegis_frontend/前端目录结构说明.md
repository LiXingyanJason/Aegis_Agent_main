# Aegis PA 前端目录结构说明

本文根据当前 `Aegis_backend/app` 的实际模块，以及《第01期-接口设计.md》的一期范围拟定前端目录。当前后端已经实现 OIDC JWT 验证、本地用户/租户映射和 `POST /conversations`；邮件、确认、记忆等前端模块先按接口设计预留，待对应后端接口实现后接入。

```text
aegis_frontend/
├── public/                              # 不参与构建的静态资源，如 favicon
│
├── src/
│   ├── api/                             # Aegis 后端 HTTP 接口封装
│   │   ├── http.js                      # Axios 实例、Bearer Token 自动携带、401 统一跳转登录
│   │   ├── conversation.js              # 已实现：POST /conversations；后续消息、运行、SSE
│   │   ├── mail.js                      # 预留：邮件列表、摘要、待办草稿、邮件草稿
│   │   ├── approval.js                  # 预留：逐项批准、拒绝待确认操作
│   │   └── memory.js                    # 预留：长期记忆的查询、编辑、删除
│   │
│   ├── assets/                          # 参与构建的图片、图标与样式资源
│   │   └── styles/                      # 全局样式、主题与 Element Plus 样式覆盖
│   │
│   ├── components/                      # 可复用的业务或布局组件
│   │   ├── AppSidebar.vue               # 登录后左侧导航与当前身份摘要
│   │   ├── AppHeader.vue                # 顶栏、退出登录入口
│   │   ├── MessageBubble.vue            # 用户 / Agent 消息气泡
│   │   ├── ProgressPanel.vue            # 任务运行步骤与 SSE 进度
│   │   └── ApprovalItem.vue             # 单项外部写入确认卡片
│   │
│   ├── router/
│   │   └── index.js                     # 页面路由、OIDC 回调路由、登录守卫
│   │
│   ├── store/                           # Pinia 状态管理
│   │   ├── auth.js                      # 登录状态、当前用户展示信息、Token 生命周期状态
│   │   └── conversation.js              # 当前 conversation_id、消息、run_id、SSE 状态
│   │
│   ├── utils/

│   │   └── format.js                    # 日期、错误提示等通用格式化
│   │
│   ├── views/                           # 路由级页面
│   │   ├── LoginView.vue                # 触发跳转到 Keycloak；不输入或保存密码
│   │   ├── AuthCallbackView.vue         # OIDC 回调，完成 Token 处理后进入工作台
│   │   ├── TaskConsoleView.vue          # 会话创建、任务输入、消息和执行进度
│   │   ├── MailManagementView.vue       # 预留：收到、保存草稿、已发送邮件
│   │   ├── ConfirmationView.vue         # 预留：逐项确认外部操作
│   │   ├── MemoryView.vue               # 预留：长期记忆维护

│   │
│   ├── App.vue                          # 根组件
│   └── main.js                          # Vue、Pinia、Router、Element Plus 启动入口

└── 前端目录结构说明.md                  # 本文档
```

## 与当前后端的对应关系

| 后端模块 | 前端对应模块 | 当前状态 |
| --- | --- | --- |
| `security/auth_security.py`、`security/dependencies.py` | `utils/oidc.js`、`api/http.js`、`router/index.js` | 后端已实现，前端待实现 |
| `service/identity_service.py`、`repository/user_repository.py` | `store/auth.js` | 后端负责真实映射；前端只保存展示状态，不保存本地权限判断结果 |
| `controller/conversation_controller.py` | `api/conversation.js`、`TaskConsoleView.vue` | `POST /conversations` 已实现，可优先联调 |
| `service/conversation_service.py`、`repository/conversation_repository.py` | `store/conversation.js` | 后端目前只实现创建会话，消息与 SSE 待继续开发 |

## 依赖与安全约束

- `utils/oidc.js` 使用 Keycloak 的 OIDC 授权码模式 + PKCE；不得实现用户名密码表单，也不得调用开发测试专用的 Direct Access Grant。
- `api/http.js` 只从 OIDC 客户端获取短期 access token，并添加 `Authorization: Bearer <access_token>`；不得在请求中传递 `user_id`、`tenant_id`。
- `.env.*` 仅保存 `VITE_API_BASE_URL`、`VITE_OIDC_AUTHORITY`、`VITE_OIDC_CLIENT_ID`、`VITE_OIDC_REDIRECT_URI` 等公开配置，不能保存数据库密码、模型密钥或 Keycloak 管理员密码。
- `node_modules/` 是安装产物，不纳入 Git；`package.json` 和 `package-lock.json` 必须纳入 Git。
