# 执行与工作流限制集中策略

实现日期：2026-10-13。集中的是规则来源，局部计数与图路由仍属于Workflow。
不提供数据库管理页面、模型修改额度或配置热更新。

## 1. 文件职责

```text
harness/
├── policies/
│   ├── execution.py       # run全局预算、超时、可信run_type工具范围
│   ├── workflow.py        # MainContextPolicy、MailCollectionPolicy
│   ├── output.py          # 格式修复、只读重试、大小与提示词裁剪
│   └── validation.py      # 构造时限制校验
├── policy_provider.py     # 不可变PolicyBundle与版本注册／查询
├── policy.py              # 旧TaskExecutionPolicy导入路径兼容，无重复规则
├── context.py             # 协程内绑定run固定策略包
└── executor.py            # 全局执行治理、事务与审计编排
```

| 策略 | 当前固定harness-v1值 | 执行位置 |
| --- | --- | --- |
| TaskExecutionPolicy | 模型10次、工具6次、活跃120秒；模型单次60秒、工具20秒 | HarnessExecutor／GuardedLLMClient |
| MainContextPolicy | 卡片读取2次、主决策3轮、累计结果24000字节 | MainDecisionWorkflow |
| MailCollectionPolicy | 收集5轮、证据12000字节 | MailCollectionWorkflow |
| OutputPolicy | 格式修复最多1次、瞬时故障只读重试最多1次 | MainAgent／MailAgent／CalendarAgent、ToolGateway |
| OutputPolicy大小限制 | 单次卡片12000字节、工具原始输出2000000字节 | CardContextService、ToolGateway |

OutputPolicy还集中历史消息数量／字符裁剪等上限。字符数、字节数和Token不是同一单位。
邮箱格式、日期范围、标题长度、卡片最多20项等属于数据契约，不因放宽策略而自动放宽Schema。
修复与只读重试允许配置为0或1，不能变为无界循环；写工具仍禁止自动重试。

## 2. 注入与运行

Worker启动时构造PolicyProvider并注入Harness及模型Agent。scope(run)开始时：

1. ExecutionRepository.ensure_budget原子创建或读取run_execution_budgets。
2. 首次写入默认策略包版本；已有任务返回原policy_version，不改计数、耗时或版本。
3. Provider按原版本查询完整PolicyBundle，并绑定当前协程上下文。
4. Workflow、Agent、Gateway和CardContextService均读取同一run固定包。
5. 局部额度检查仍在Workflow节点；模型／工具实际调用再检查全局Harness额度。

MainDecisionWorkflow／MailCollectionWorkflow把execution_policy_version写入State。
恢复后先检查它与数据库固定包一致，再执行读取／推理；旧Checkpoint无此字段时使用数据库原版本，
不会重置已有context_round、context_read_count或collection_round。
没有scope的独立图测试可显式注入Provider，按State版本解析；生产必须由Worker的Harness scope执行。

## 3. 计数语义

- 一轮主决策指一次语义决定；格式修复属于这一轮，但每次LLM请求都占模型全局次数。
- 局部卡片额度统计每个工具请求尝试，读取失败也占用。Gateway瞬时故障重试另占全局工具尝试。
- 邮件收集轮次包含调用工具、询问用户和决定生成草稿；用户等待不计活跃执行时间。
- 局部额度有余额也必须满足全局额度；它不是赠送的新预算。
- SQL／身份／版本核验不是新的模型调用，不按图节点数扣减模型／工具次数。
- 局部耗尽保持原行为：主图澄清context_budget_exceeded，邮件收集失败REACT_BUDGET_EXCEEDED。
- 全局耗尽使用EXECUTION_BUDGET_EXCEEDED；MODEL／TOOL超时仍沿用EXECUTION_TIMEOUT。

## 4. 改限制时注册新版本

不能直接修改已发布LEGACY_POLICY或同一个版本的值；PolicyProvider注册版本不可重复，数据对象不可变。
旧版本的全部数字和工具范围保留为显式快照，避免修改dataclass默认值影响恢复任务。

示例（仅示范，当前生产仍默认harness-v1）：

```python
from dataclasses import replace
from aegis_agent_worker.harness.policy_provider import PolicyProvider, LEGACY_POLICY
from aegis_agent_worker.harness.policies.workflow import MainContextPolicy

v2 = replace(
    LEGACY_POLICY,
    execution=replace(LEGACY_POLICY.execution, version="harness-v2"),
    main_context=MainContextPolicy(max_reads=3, max_rounds=4, max_context_bytes=24000),
)
provider = PolicyProvider((LEGACY_POLICY, v2), default_version="harness-v2")
# Worker：HarnessExecutor(database, policy_provider=provider)
```

已有harness-v1任务仍使用2次读取／3轮；新run才用新版。修改局部策略也必须升级整个包版本，
不能只改主Agent提示词里的次数。剩余次数由同一策略计算。
数据库保存版本引用，不保存整个配置快照；代码发布必须保留旧版本定义，
不能假定数据库能够检测“有人在代码中偷偷改了同名策略的值”。

原版本缺失：POLICY_VERSION_UNAVAILABLE；State与数据库版本冲突：POLICY_VERSION_CONFLICT。
这两类情况不静默换默认策略、不执行模型／工具，也不重置计数；先恢复正确配置或重新提交任务。

## 5. 审计与部署

复用run_execution_budgets.policy_version保存整个策略包版本，无新增表或迁移。
run_execution_attempts通过run_id关联该版本；main_decision_completed增加可选execution_policy_version。
局部计数继续在Checkpoint State中，不把图内控制逻辑塞入Repository／Gateway。
前端可以忽略新增审计字段。暂停／审批和Redis恢复消息格式不变。

部署前等当前消费结束，再重启Worker；不要清空Checkpoint或手动改旧预算版本。
默认值保持不变，旧harness-v1记录可直接继续使用。
