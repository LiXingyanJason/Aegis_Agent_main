# 主后端接口、SSE与来源卡片（6.6）

## 范围

首期链路已接通：上传保存→显式索引→显式启用→对话知识查询→SSE刷新来源卡片→点击来源重新授权读取。
资料页增加分页、详情、共享／收回共享及软删除；知识回答沿用6.5引用约束。
遵循此前暂缓完整版本管理的决定：不实现POST versions、多版本切换、历史恢复或源文件下载。
本阶段的版本路径用于绑定已有来源，不代表开放多版本产品功能。真实云端／OIDC浏览器端到端验收仍待6.7。

## 1. 主后端接口

完整契约追加在根目录《第01期-接口设计.md》篇末第9章，不在3.x中间插入。

| 接口 | 行为 |
| --- | --- |
| GET /knowledge/documents?limit=50&offset=0 | 保持data数组兼容，limit为1～100，offset为0～100000；按created_at DESC,id稳定排序 |
| GET /knowledge/documents/{document_id} | 当前可见资料元数据、v1标识／标签、索引状态与已索引片段数；不返回路径／原文／模型密钥 |
| PATCH /knowledge/documents/{document_id}/visibility | 所有者提交private／tenant，立即收回或授予同租户共享读取，不自动启用／索引 |
| DELETE /knowledge/documents/{document_id} | 仅所有者软删除，204空响应；deleted_at记录时间、enabled=false，不清除文件／向量／审计 |
| GET /knowledge/documents/{document_id}/versions/{version_id}/chunks/{chunk_id}?content_hash=... | 按当前身份／启用／ready当前版本／片段已索引／hash复核后返回有界来源摘录 |

原有文本／文件上传、索引启动／重试、启用／禁用及任务轮询接口保持不变。
详情允许当前可见的未启用／未索引资料，因为它是管理元数据；来源正文必须启用且ready、非敏感、允许外发。
共享读者can_manage=false，不提供别人的job_id；仍能看到ready状态，不能读取其私人索引任务进度或执行管理操作。
不存在／非本人管理操作统一404；来源不存在、失效、未启用、错文档／版本、hash变化或无权读取统一404 KNOWLEDGE_SOURCE_UNAVAILABLE。
UUID／hash／分页／分享参数非法为422；不接收文件路径、任意URL、租户或用户身份字段作查询授权。
来源GET及Artifact读取返回Cache-Control:no-store；来源404同样不允许缓存。

来源响应只含document_id、version_id、chunk_id、title、version_label、section、start_offset、end_offset、excerpt、content_hash。
excerpt最大取800字符，不返回整份源文件；位置为索引原文字符偏移，不是源文件字节偏移。
Hash绑定版本／片段内容，不能拿另一段或新内容替代；前端还比较卡片与详情的元数据、位置及摘录，变化即要求重新查询。
这是只读授权访问，不创建run、调用LLM／Embedding或修改外部服务。

## 2. Worker进度与SSE

KnowledgeWorkflowProgress只处理SQL步骤与事件：

```text
知识子图plan → knowledge_planning（正在规划知识查询）
检索服务    → knowledge_search（正在检索知识资料，原有步骤）
知识子图answer → knowledge_answer（正在生成来源约束回答）
Artifact持久化 → artifacts_ready（仅标识／类型／会话）
Lifecycle     → assistant_message_completed → run_completed
```

每个规划／回答阶段有running及succeeded／failed的progress_updated，使用真实step_id。
模型调用期间不持有SQL事务；阶段完成事务结束后才发布事件，错误事件不带原始异常或正文。
只复用既有Redis Pub/Sub、持久run_events与SSE，不增加索引任务SSE。
前端仍在artifacts_ready／assistant_message_completed后调用Artifact API，完成任务时也沿用刷新；
Last-Event-ID断线补发、按event_no去重、任务归属鉴权不变。
事件中的标识不是来源授权；历史事件重放后读取卡片仍要走当前SQL复核。

## 3. 前端

- TaskConsoleView识别knowledge_sources，KnowledgeSourceCard展示编号、标题、版本、章节、位置、摘录及冲突／失效提示。
- 回答中的规范[n]只为当前已返回来源生成按钮，点击后KnowledgeSourceDialog使用三个UUID与hash调用来源GET。
  未知编号保持纯文本，不拼模型提供的链接、不解释HTML／Markdown；标题、章节和摘录也以Vue文本渲染。
- 每次详情请求先清空旧内容；请求取消、切换来源和会话都有竞态保护，失败不退回缓存。
- 卡片刷新开始即暂时移除旧知识摘录；失败显示不可用，较早请求不得覆盖更新结果。
  返回页面重新获得焦点时关闭旧详情并重新核验知识卡片，用户可手动重新核验。
- available／partial／unavailable沿用6.5；partial保留历史编号，不把剩余依据自动当作唯一权威。
- 资料页保留原三步导入流程，增加元数据详情、可见范围确认、软删除确认以及每页100条分页；本地标题／状态筛选仅当前页。
  管理操作以服务端can_manage与身份复核为准，不靠隐藏按钮授权。

不显示向量／RRF分数为可信度，不显示后端服务器路径、密钥或ACL。
不能收回已读内容，不自动擦除既有助手消息、Checkpoint、审计快照或用户截图。
删除只停止后续访问，不是远端对象物理删除／取消已在途网络请求；文件和索引清理仍单独治理。

## 4. 新增迁移015与部署顺序

代码head为015_knowledge_version_binding，先备份并暂停旧API与两个Worker，再在Aegis_backend执行：

```powershell
D:\anaconda\envs\Aegis\python.exe -m alembic upgrade head
D:\anaconda\envs\Aegis\python.exe -m alembic current
```

期望015_knowledge_version_binding (head)。随后一起部署／重启API、Agent Worker、Index Worker与前端。
本次没有对现有业务库执行升级，所有真实数据库验证只在临时schema回滚。

迁移有两项明确用途：

1. 给版本增加vector_namespace／vector_collection，并从已有索引任务回填；Index Worker后续在准备片段的同一事务中固定它们。
   旧检索scope从仅所有者可见的knowledge_index_jobs取绑定，受限角色查询共享资料时会误判集合不匹配。
   现在从已获授权的版本读取绑定，仍核对SQL模型空间登记；不开放别人的job行，不重新索引、不改写向量集合。
   缺失绑定仍明确不可用，不猜测目标集合；若旧任务没有可回填绑定，应检查索引状态并按已支持流程处理。
2. PostgreSQL UPDATE还会校验新行SELECT策略。为了让所有者完成软删除，文档RLS允许所有者内部看到自己的已删除元数据；
   API继续显式deleted_at IS NULL，不公开已删除资料。版本、片段的SELECT及ALL策略和索引任务策略同时增加deleted_at IS NULL，
   所以所有者也不能通过内容子表读回已删除原文；共享者和其他租户仍不可访问。

不能仅调整文档策略而遗漏FOR ALL子表策略。迁移不取消FORCE RLS，不使用超级用户运行请求来绕过检查。
生产运行账户仍应无BYPASSRLS；迁移使用有DDL权限的维护账户。降级前停止新版API／Worker，015会移除版本绑定列并恢复旧策略。
