# 7.5 记忆优先级、用户管理与撤销

## 范围与边界

完成确定性选择、调用级追溯、用户取消确认以及旧审计正文清理。不做时间衰减、统一过期天数、自动续期/确认、聊天自动写入、向量记忆检索或多模型选择。

当前明确要求仍优先于记忆。记忆是低优先级数据，不覆盖系统规则、工具事实、授权、用户明确时间/参会人、用户确认后的草稿版本。用途白名单沿用7.4及日历逐步骤规则；不向主路由、事实提取、知识证据回答或审批开放个性化记忆。

## 选择链路

`GuardedLLMClient → MemoryContextService.prepare_call → MemoryRepository.recall_candidates → selection.rank_and_resolve → MemoryContextBundle → 调用前版本复核/安全审计 → 模型`

1. PostgreSQL先过滤tenant/user、允许类型、已确认、非敏感、未删除、未过期、来源可访问/版本有效。
2. 任务提取有界中文双字词项/英文词，SQL先匹配和分档，再返回有界候选。不会先按“最新50条”截断后才搜索。
3. 排名为相关结构实体 > 至少两个直接词项命中的摘要 > 单词项/时间领域弱匹配摘要。实体使用受Schema校验的字段，不用自由说明替代结构字段；联系人必须在当前任务中明确匹配姓名或邮箱。
4. 在截断前，SQL按定义的主题聚合摘要差异和实体存在性；实体压过同主题摘要，不同内容的同主题摘要保守排除，不由更新时间猜测哪个正确。主题基线为timezone/reply_style/meeting_preferences/contact/unknown；无法判定的摘要与相关实体并存时也排除。此规则不是语义矛盾识别器，可能将兼容摘要保守排除，用户可在页面整理为结构设置或一条明确摘要。
5. 同档用更新时间、ID稳定排序；更新时间仅是平局规则，不是时间衰减。相同类型的相同规范化正文去重保留最新记录。
6. 按条数、单条字符、总字符、UTF-8字节以及剩余输入预算逐条选取。结构字段不截断；摘要最多取安全有界摘录。无可用候选或SQL失败时不带个性化记忆继续原用途，不伪造来源。

策略统一由`PolicyProvider.current().memory`提供，独立排名版本`memory-rank-v1`。默认候选50、查询词32、任务文本4000字符、直接强匹配阈值2、SQL超时2秒、安全排除审计最多50项；原5条/单条400字符/总1500字符/6000字节额度不变。额外取1条探测召回截断，不宣称无限召回。超出范围的记录不逐条输出；主题冲突仍在LIMIT前汇总，防止截断后误当无冲突。

## 调用审计与用户追溯

- `run_execution_attempts.memory_selection_details`只保存排名版本、检查数量、召回截断标志、排除ID/版本/原因和原因计数。不保存候选正文、完整Prompt或新全文副本。
- 原`run_memory_usages`继续保存真正注入的ID、类型、来源/版本、attempt关联及使用理由。供应商Token为整次调用的可空值，不是每条记忆费用；无可信tokenizer时预计Token仍unknown。
- 新`GET /runs/{run_id}/context-summary`先验证任务归属，返回有界attempt列表、实际使用引用及当前可用性；历史未关联attempt的行单列，不补造版本、调用或Token。
- 对已删除、撤销、敏感、失效或变更的记忆不返还正文；不可用来源的对象ID/版本也不返还。接口不读取`content/display_summary`，禁止缓存。内部排除明细不原样返回，只返回白名单原因计数与`needs_review`。
- 前端任务旁提供“查看记忆使用情况”，可手动重新核验；切换任务/会话、关闭或请求失败会清除旧结果。长期记忆页提供“取消确认”。本次无新增SSE工具触发约定。

## 更正、取消确认与删除

- 更正沿用PATCH：版本CAS，保存后pending，核对后再确认。
- `POST /memories/{memory_id}/revoke`传`expected_version`；仅当前用户的confirmed行可取消确认，状态revoked、版本+1、删除令牌失效，保留正文供用户管理。再次生效须编辑成pending并重新确认。
- 两步删除接口保持不变。取消确认不等同删除，历史使用事实不被伪造为从未发生。
- 每次真实模型调用、修复或恢复重新查PostgreSQL；提交使用审计时再次核验版本和来源，变化则阻止发送旧摘录。不能撤回变更提交前已经发送给供应商的请求，也不重写历史生成结果。
- 当前没有长期记忆正文的Redis/向量缓存。本次不新增缓存，因此不依赖异步缓存清理实现撤权。未来缓存只能给候选ID，仍须回SQL复核。

## 迁移与部署

新增revision：`020_memory_selection_revoke`，父revision `019_calendar_memory_preferences`。

1. 停止API写入和Agent Worker并备份数据库；不可与仍写旧审计正文的Worker混跑。
2. 在`Aegis_backend`执行`python -m alembic upgrade 020_memory_selection_revoke`。
3. 更新API、Worker、前端，再启动。运行角色需保留既有RLS及新列/表的必要读写权限，包括run_memory_usages的UPDATE；不得提升为超级用户绕过RLS。

迁移新增安全诊断JSON列/大小约束和召回索引；**会清空全部历史run_memory_usages.display_summary正文副本**，保留记忆源正文、ID、使用事实及其余审计元数据，并增加禁止再次保存该列正文的约束与变更清理触发器。降级不恢复已清理的副本；恢复只能依赖事前备份，不能从审计页面读取旧正文。

本次未迁移业务数据库。真实SQL测试仅在随机临时schema、受限角色与回滚事务中执行，不调用模型、Qdrant或Redis服务。

## 验证

- 固定选择集：较旧强相关、实体优先、不同摘要保守冲突、重复去重、未知摘要排除、SQL范围外冲突标志，倒序输入结果一致；不是模型质量或召回率提升实验。
- 临时PostgreSQL：超过50条近期记录仍召回较旧强相关记录；敏感/待确认过滤；真实取消确认、版本冲突、删除令牌失效、跨用户隔离、历史正文清理与拒绝再写正文。
- API：归属检查、严格版本参数、撤销成功/冲突、404、查询上限、安全元数据和unknown Token。
- 每次调用/删除后修复与恢复重读沿用7.4回归；前端测试与生产构建通过。7.6的综合离线收益、P95与真实交互验收仍需单独执行，不提前声称通过。
