## 2. 环境、授权与隔离

模型为 `api.deepseek.com / deepseek-flash`。用户授权仅外发虚构数据，允许模拟补问和审批并写入隔离 Mock 日历。E07 正式 954 次、冒烟 11 次，共 965 次，低于授权 1920 次；E09 正式 363 次、冒烟 4 次，共 367 次，低于授权 714 次。E08 无真实模型调用。不计算未经核实的金额。

执行基于提交 `6361f68855e9488e3cb1413a27712915accbb478`；Worker src 哈希 `5a6b8902044250d3b12f7826df5f3558034942349160d9f56731ce120f5d28c6`，具体数据与指南哈希保留在 metadata。未修改前端。

E07 使用随机独立数据库并迁移到 022、独立 Redis 队列、独立 Mock 文件和本地 TCP MCP。真实 API 路由在 ASGI 进程内执行，认证依赖替换为固定虚构身份；Worker、持久化事件、补问恢复、审批及 Checkpointer 使用生产实现。不是 OIDC、浏览器或真实邮件/日历测试。E08/E09 使用隔离 schema、最小支撑表及实际 Repository；E09 应用实际 022 迁移，不能宣称全库迁移或角色 RLS 验收。

各次 metadata 记录数据库/schema 清理成功；E07 执行器清理独立队列和 MCP 进程。第一次环境探针误等待 SSE 流结束，未调用模型即中止；只修正探针，遗留实验数据库已按精确名称清理，保留 env 日志。不删除业务数据。

## 3. E07 协作端到端

### 方法及与计划的差异

入口是自然语言“按续约邮件要求查询日历并安排会议草稿”，经过主路由、协调者、邮件专家、日历专家、补问和人工确认。模拟用户只依据冻结标准回答与审批。30 个样例由模板变体生成，包括明确来源、多邮件选择、字段缺失、拒绝、无结果、时间冲突、正文注入、来源变化、连接撤销和草稿版本变化；不等同于 30 个独立业务分布。部分变体仅更换名称、日期、时长。使用绝对日期，未冻结系统时钟；C01 在开发冒烟出现过。关闭记忆、Skills、知识检索，避免实验混杂。

核验脚本逐项检查实际事件：所选邮件 ID、单次写入、时间窗口、时长、参会人集合、无日历冲突、与审批预览一致及对应 `approval_executed` 回执。49 次写入均通过这些检查。其余参会人日历仍不可核验，不能声称确认所有人均空闲。

| 指标 | 结果 |
| --- | --- |
| 预期写入闭环 | 49/63，77.78% |
| 按样例聚类 bootstrap 95% 区间 | 65.08%–88.89%（10000 次，seed=20261025） |
| 预期不写入 | 27/27 无实际事件 |
| 实际事件 / 重复事件运行 | 49 / 0 |
| 模型外发 / 审计 model attempts | 954 / 956 |
| 已知供应商 Token / usage unknown | 1,629,769 / 2 attempts |
| 工具 attempts | 439 |
| 平均 / P95 墙钟耗时 | 23.66s / 35.63s |

两条无 usage 的失败 attempt 位于 C02 第 3 轮，错误为 `EXECUTION_FAILED`，不能填成零 Token。计数器记录模型外发 954 次，不以 956 条持久化 attempt 替代外发数。耗时包含脚本自动回答及审批等待，不代表人工真实等待，也无法由现有导出还原纯活跃时长。

### 失败与限制

14 次未完成写入：7 次邮件规划结构化输出无效，1 次日历输出无效，1 次协调决策无效，5 次草稿参会人不符合测试要求。详细 case/repeat 见 `verified_summary.json`。

5 次草稿问题包含 C15 三轮、C18 第 2 轮和 C12 第 3 轮。C15 源邮件没有参会人，测试期望补问，但产品允许可选参会人；这是验收口径差异，仍按冻结标准记失败，不事后改分母。C18/C12 则需要检查现有来源信息在交接或草稿生成时丢失的问题。

不写入的 27 次中：9 次主动拒绝、6 次等待进一步信息或新时间窗口、9 次来源/连接/版本变化阻断、3 次无匹配来源。最后一组 C22 第 1 轮实际为 `MODEL_OUTPUT_INVALID`，另两轮为 `MAIL_MEETING_SEARCH_NO_PROGRESS`；不能把所有无写入都算作正确解释。原始机械评分 76/90 仅保留用于追踪，不作为总任务正确率。脚本拒绝了错误草稿，因此“零错误写入”同时依赖人工确认环节，不能宣称模型从不生成错误草稿。

## 4. E08 Harness 边界与故障

48 项新矩阵覆盖模型/工具额度、scope、保留参数、写入批准门、非法 schema、超时、输入/输出额度、任务状态、恢复累计预算、稳定错误审计，均通过。它使用实际 Harness/Gateway，但存储为测试替身。86 项既有测试包括治理、审批、策略、Skill 生命周期和输入选择，不与新矩阵合并成安全成功率。

真实 PostgreSQL 实验调用实际 ExecutionRepository：100 轮两个异步请求竞争最后一个模型额度，均只成功一次且持久化使用量为 1。另验证错误用户/租户/策略、终态和暂停状态、时间耗尽、恢复保留政策与用量，共 9 项通过。没有压力吞吐指标，也没有测试角色 RLS。

新增 4 项实际本地 MCP Server 测试组合批准/未批准与正常/丢失回执。回执丢失在适配器成功调用后注入：外部已写入但 Harness 收到不可用错误；没有自动重试写入。测试显式用同一幂等 key 再调用仍只有一个事件；未批准时 MCP 调用数及事件数为零。这不是 TCP 代理断流实验，也不代表生产已具备自动对账恢复。

另有协作相关既有离线测试 92 项通过，单独保留 XML，不计入 E07 端到端分母。

## 5. E09 Skill 配对实验

30 题 × 3 轮 × 3 组，共 270 个输出，同题同轮随机化组顺序。A 不使用 Skill，B 固定加载指南，C 生产按需选择。三组使用相同预算策略；B 的固定选择为实验适配，读 Skill 和版本复核仍走生产组件。只有一份续约指南，标签为作者预标注，不能外推多 Skill 检索能力。

| 指标 | A 无 Skill | B 固定指南 | C 按需指南 |
| --- | ---: | ---: | ---: |
| 输出成功 / 样本 | 90/90 | 90/90 | 90/90 |
| 模型请求 | 90 | 93 | 180 |
| Skill 读取 | 0 | 90 | 53 |
| 修复调用 | 0 | 3 | 0 |
| 供应商 total tokens | 34,331 | 59,797 | 88,933 |
| 平均耗时(s) | 1.661 | 1.866 | 3.088 |
| P95耗时(s) | 2.969 | 3.594 | 4.547 |

C 应加载 54 次，实际命中 53 次；36 次不适用均未加载。召回 98.15%，精确率 100%，误加载 0/36。漏选为 S30 第 2 轮。所有正式调用 usage 已知，合计 183,061 Token。C 减少指南读取，但引入选择模型调用，其 Token 比 B 高约 48.72%，不能写降本。

独立语义盲评尚未完成，已生成 `blind_review.json` 和独立映射 `review_key.json`。不填最终内容质量通过率，也不伪造配对质量增益及置信区间。

事后新增探索性检查仅选 6 题明确格式/字面要求（S17/S22/S23/S25/S29/S30），18 次观察/组：A=14/18，B=14/18，C=12/18。这是查看输出后设计的辅助评分，不是预注册主指标，不能外推整体质量。抽查发现 C 可能忽略“一句话”或添加未要求的期限；指南不能取代本轮明确要求。当前没有支持 Skill 改善质量的证据。
