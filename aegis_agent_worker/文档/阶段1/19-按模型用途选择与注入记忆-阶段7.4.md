# 按模型用途选择与注入记忆（7.4）

实施日期：2026-10-19。统一根图普通回复、邮件回复起草及草稿正文完善的记忆接入；不增加自动记忆写入、向量召回或新前端接口。

后续日历扩展已完成，见[日历逐步骤结构化记忆](20-日历逐步骤结构化记忆接入.md)：当前部署需迁移019，以下018部署记录描述本阶段原始基线。

## 1. 用途与额度

| 模型用途 | 可选候选类型 | 注入策略 |
| --- | --- | --- |
| conversation_reply | 已确认的长期摘要、实体 | 与本轮任务相关时才选择 |
| mail_reply_draft | 已确认的长期摘要、实体 | 按起草要求选邮件语气等偏好 |
| mail_draft_revision | 已确认的长期摘要、实体 | 按补充要求选偏好，当前要求优先 |
| calendar_planning | timezone实体，最多1条 | 仅代码解析时区，不注入自由文本摘要/会议软偏好 |
| calendar_draft_personalization / calendar_recommendation | timezone、meeting_preferences实体，最多2条 | 只在可信候选中推荐，不能判断空闲或批准写入 |
| 主路由、邮件领域规划/事实提取/信息收集、知识规划/证据回答、审批及其他未知用途 | 无 | 不查询记忆、不注入个性化 |

原三个允许用途分别使用 `MemoryContextPolicy.types_for(purpose)` 白名单；统一额度为：SQL候选最多50条、最终最多5条、单条400字符、合计1500字符/6000 UTF-8字节。日历用途叠加上述实体key白名单及1/2条上限。
额度均从 `PolicyProvider.current().memory` 获取，跟随原任务固定策略包，不因恢复重置Harness预算。
还需满足本次模型输入剩余字符额度；计算包含JSON包装及转义后的长度，装不下则少选或不选。
实体必须通过Schema且整体容纳，不截断邮箱/时区。长摘要只取有界摘录。

未部署可信tokenizer，`estimated_tokens=null`，默认不启用记忆Token硬上限。
若显式配置 `max_estimated_tokens`，估算未知时返回空Bundle及 `token_estimate_unknown`，不以字符数猜测Token。
供应商返回的Token是整次请求的真实用量，不是每条记忆的精确成本；没有报价/金额推算。

## 2. 调用关系

```text
TaskGraph._generate_reply / MailReplyDraftWorkflow / MailRevisionWorkflow
  → memory_call_scope(service, 原run, 用途, 当前任务要求)
  → GuardedLLMClient（每一次首次/格式修复调用）
      → HarnessExecutor.attempt：预算占用、创建真实attempt_id、超时
      → MemoryContextService.prepare_call
          → MemoryRepository：当前租户/用户的有效SQL记录
          → 确定性相关性、实体Schema、条数/字符/字节/剩余输入额度
          → MemoryContextBundle
      → 格式化为低优先级user数据，放在系统消息之后、当前任务要求之前
      → MemoryContextService.record_call：再次复核版本/来源并记录安全关联
      → 模型通信
      → finish_call：回填整次调用的供应商usage
      → Harness收尾：attempt状态、用途、记忆数量与筛选结果
```

`memory_call_scope`仅使用协程局部ContextVar声明可信请求，退出必定reset；不保存SQL会话，不进入LangGraph State。
允许用途还必须与当前调用用途相等，且请求的run/tenant/user与Harness已领取任务一致。
无声明、用途不允许、内部用途被切换时，不能借外层起草作用域获得记忆。

生产路径不再使用 `select_for_run + format_system_context` 或 MailAgent 任意记忆字符串/加载回调。
专家继续只负责语义推理；SQL和筛选在Service/Repository，模型通信仍复用既有Client，执行预算仍复用Harness。

## 3. 筛选与失败策略

SQL在读取正文前同时限定：当前tenant/user、未删除、confirmed及确认时间、normal且非敏感、未过期，以及 `aegis_memory_source_accessible` 的当前来源权限/版本。
按更新时间、ID确定性排序；中文双字词项/英文词项交集及既有时间/邮件偏好规则作为最小相关性基线，不用模型自行授权。
没有引入Redis/向量记忆候选；未来增加候选缓存也必须先回SQL核验再读正文。

Bundle包含run/用户/会话（页面任务可null）/用途/策略/选择时间，以及记忆ID、版本、类型、来源、摘录与原因。
手动来源以该记忆ID/版本作为稳定引用，不伪装为对话或知识资料；业务来源保留真实对象ID/版本。

- 不相关、额度不足、估算未知：空Bundle，正常执行不带个性化的模型请求。
- 可选记忆查询失败：空Bundle，审计 `memory_unavailable`；不额外调用模型修复。
- 非法实体/坏记录：忽略，不把正文或校验错误输入写入日志。
- Harness全局调用预算耗尽：在读取记忆及模型通信前拒绝，不追加重试。
- 已选择记忆在审计提交时发生版本/权限/有效期变化：`MEMORY_CONTEXT_CHANGED`，阻止本次带旧摘录的请求；不是格式错误。
- 记忆使用审计提交失败：不发出带记忆的模型请求，不静默绕过审计。

这是调用前快照复核，不能撤回已经发送给供应商的请求，也不宣称能消除所有提示注入风险。

## 4. attempt级审计（018迁移）

`run_execution_attempts`新增：

- `memory_count`：本次请求选择并装配的记忆数量，禁用/空结果为0；历史为null。
- `memory_policy_version`、`memory_selection_reason`：安全策略和筛选结果，不含用户正文。

`run_memory_usages`新增：

- `attempt_id`、`model_purpose`，关联原run的真实模型调用。
- `memory_version`、`memory_type`、`source_kind/source_object_id/source_version`。
- `selection_reason`、`policy_version`、`excerpt_bytes`、可空 `estimated_tokens`。
- 可空 `call_prompt_tokens/call_completion_tokens/call_total_tokens`。

保留旧 `usage_purpose='context'` 以兼容原约束；新 `model_purpose` 表示具体模型用途。
新增记录不写 `display_summary` 或完整Prompt/记忆正文；旧行不伪造attempt/Token，也不删除旧数据。
复合外键约束attempt/run/tenant对应，唯一索引防同次调用重复记同一记忆；写入SQL同时复核attempt用户与记忆归属/版本/来源。
无选中项不插入逐条使用行，直接从attempt的0数量与原因查看。

供应商失败的attempt必须结合status/error_code分析；有选中关联不代表请求成功、供应商一定处理或产生了Token。
多条记忆共享同一组整次调用Token，统计Token必须按attempt去重，不能累加每条使用记录造成重复计费。

## 5. 恢复与页面任务

页面起草/修改沿用页面任务本人的run，无需伪造conversation_id。
审批/补充问答仍使用原run/thread和原任务要求；真正再次调用模型时重新查库，不使用旧Checkpoint的 `memory_context` 摘录。
邮件格式修复同样重新查询，并产生独立attempt关联；不会把首次带记忆的临时消息写回重试消息模板。
删除、过期、来源删除/撤权/版本失效后，下一次调用不会继续注入旧值。审批恢复本身不新增个性化调用，正式写入仍读取已批准的草稿版本。
