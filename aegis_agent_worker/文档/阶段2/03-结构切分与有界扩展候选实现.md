## 1. 模块及调用

- `indexing/structural.py`：`parse_structure(text, scope, policy)`返回`StructuralIndex(chunks, relations)`；仅显式调用才使用，不替换生产`paragraph-v1`。
- `StructuralPolicy`：实验默认size700、overlap80、最大512块／262144字符；硬上限800字符，参数校验，无Token换算。
- `StructuralIndex.enhanced(title)`：按title-path-v1生成独立检索文本及哈希，不修改原文。词项／向量使用哪种文本由实验显式选择，本次仅离线词项代理，不声称向量增强已上线。
- `retrieval/expansion.py`：纯函数`expand_evidence`接收可信已授权完整结构快照、原文及直接命中，返回多范围`EvidenceContext`和额度／不完整诊断。它不能自行查询数据库或证明授权，禁止直接暴露为模型工具。
- `scripts/evaluate_structural_candidates.py`：在3.1冻结语料上生成结构-only、结构＋标题、结构＋扩展、结构＋标题＋扩展四组代理轨迹；不调参、不发模型请求。

从Worker根目录运行：

```powershell
python -m pytest -q -p no:cacheprovider tests/evaluation/test_structural_candidates.py tests/evaluation/test_chunking_contracts.py
python scripts/evaluate_structural_candidates.py --output evaluation-results/structural-candidates-new.json
```

脚本拒绝覆盖已存在报告；保存每组逐题排名、交付范围、证据覆盖、不完整状态和切块正文。默认配置是待实验验证的候选，不是最优参数。

## 2. A：结构与增强

识别ATX Markdown标题树、编号条款、段落、列表及管道表格。围栏代码当普通原文处理，不把其中的伪标题加入标题路径。原始范围始终是Unicode连续切片，内容SHA-256复核后构造确定性ID，scope需指定structure-v1。

标题变化更新完整路径并终止前一章节条款归属。条款延续段落保留clause_id；相邻普通段落只在相同路径／条款且长度允许时合并。列表、表格、不同条款不混合成失去类型的块。

长单元优先句子／换行边界，重叠仅保留额度内完整尾句／行，无合适边界时不强行重叠；超长单句／行硬拆标hard_split。Markdown表格优先按行拆，每块关联原始表头范围。列表关联前一同章节引导段，超长引导段预算不足时不能伪造完整交付。表头／引导句不复制到RawChunk正文，多范围回答上下文才组合引用。

这是保守的文本／Markdown识别器，不是完整CommonMark解析器；Setext标题、复杂HTML表格、复杂围栏嵌套等不作结构理解承诺。跨章节例外不自动推断关联。语义例外识别、父级映射未实施；未来扩展必须新parser版本并回归原文范围。

## 3. B：有界选择

先保留有限直接命中，再依次考虑同条款、同章节相邻块；按触发命中顺序、距离、原文位置稳定排序。同一候选只交付一次，直接命中优先，同条款扩展保留触发ID，不伪造RRF排名。只处理同SourceScope，不扩展跨文档／版本／代次或父结构。

`ExpansionPolicy`集中管理默认最多5个直接命中、6个扩展、邻距1、3500原文字符和12000原文字节；内部契约仍限制16范围／32来源。合并接壤／重叠范围，不填补缺口，原文哈希不变。这里的字节额度统计原文，不等于最终JSON大小；生产接入仍须额外执行序列化结果大小检查，不能直接代替现有12000字节结果限制。

原文校验失败立即拒绝；直接命中不在快照标记source_unavailable／整体incomplete，额度不足标budget，不截断原文。没有已知失败也保持not_assessed，不自动宣称全部业务条件已覆盖。所有直接命中都放不下时允许返回空contexts且incomplete=true，上层不得给确定性成功回答。

输入必须是已授权的**完整有界结构快照**：邻接按快照内原文顺序计算，不能把缺少中间块的稀疏查询结果当作真实相邻块。relations范围也必须来自同一已授权原文。该前提由后续SQL适配保证，当前纯函数不是权限守卫，不能拿它接入未过滤的全库块集合。

## 4. 本次验证

`test_structural_candidates.py`10项、既有契约7项，共17项通过：标题／嵌套列表／表格、围栏伪标题、表头复用、长条款共享归属、硬拆上限、稳定切片及增强、同条款优先、预算不足、缺失／重复命中、代次隔离和错误原文拒绝。

归档`实验数据/20261102-structural-candidates-v1.json`：8份文档生成65个结构块，17题×4组=68条轨迹；external_calls=0。它是候选可运行性记录，不是3.4正式质量消融，词项交集排名不等于PostgreSQL／向量／RRF。3.1真实基线和独立标签复核仍未完成，不宣称召回／答案提升，完整质量与成本比较在3.4进行。

## 5. 生产接入尚缺的工程条件

1. 现有knowledge_chunks没有generation、标题树及结构关系字段；3.5需先设计迁移、索引任务版本和可回滚的代次切换，不把离线结构元数据塞入旧section字段或旧hash。
2. Repository须用可信tenant/user及现有VISIBLE条件，在SQL内读取同文档有效版本／代次、同条款及真实相邻关系，候选LIMIT+1超限明确拒绝。不能先加载全库再用Python隐藏未授权资料。
3. 持久化标题增强输入及哈希、明确词项和向量应用策略，复用Embedding治理及Qdrant写入；模型空间／代次不一致拒绝，不复用旧向量。
4. Service在交付前复核每个原文／表头／引导范围、触发关系与权限；补充真实SQL、撤权、稀疏缺块、索引重试与恢复测试。当前17项测试不证明这些数据库条件通过。
5. 复合范围和完整性字段需要新证据／Artifact契约、来源读取及答案引用适配；在接口文档篇末追加后再交接，旧v1及其800字符／5条／12000字节默认均不变。

上述不是可省略的检查；在完成前A/B保持离线候选，不将本节状态写为生产上线完成。3.6的C可以按冻结候选独立实验，本轮不调用重排服务。回滚当前候选仅需不调用新增模块，业务索引未受影响。
