# 开始索引后的自动化链路

日期：2026-11-02。工程实现完成；未修改业务 `.env`，未升级业务数据库，未调用真实 Embedding／Qdrant。本节替代07中“新资料必须先跑旧索引，再用CLI准备结构代次”的操作要求；历史资料的离线消融与显式重建工具继续保留。

## 1. 交互与边界

资料上传 → 用户点击开始索引并授权外发 → API保存固定配置并提交 → Redis唤醒Index Worker → 读取及校验原文 → 结构解析与切分 → 准备并校验代次 → 受治理的Embedding → Qdrant确认写入 → SQL记录进度 → 代次ready、原索引任务succeeded。

上述内部步骤均自动完成，无需逐项执行prepare／validate／enqueue命令。自动校验检查结构、来源和manifest一致性，不代表检索质量评测通过。上传、开始索引、发布代次及启用资料仍为独立行为：不会自动外发刚上传的内容，不会在构建完成时自动发布或启用资料。发布也有HTTP接口，正常产品操作无需CLI。

## 2. 新任务的配置与兼容

API新增配置，模板见 `Aegis_backend/.env.example`：

```dotenv
KNOWLEDGE_INDEX_STRATEGY=structure-v1
KNOWLEDGE_INDEX_TITLE_ENHANCEMENT=false
```

默认保持paragraph-v1，避免未经评测切换所有新资料。structure-v1选择结构切分；标题增强单独开关。原开始索引请求仍只提交 `external_embedding_allowed=true`，用户或模型不能提交任意解析器、路径、代次ID或权限参数。

API将策略、来源标题及GenerationConfig固定到knowledge_index_jobs.index_config；NULL表示原段落策略。重复开始返回原任务；失败重试沿用原任务、同一代次ID和累计预算。调整配置仅影响之后新建的任务，不能悄悄修改已创建任务的切法。已完成旧任务不会因再次点击开始索引自动升级，历史资料重建仍使用显式开发运维工具。

Agent Worker配置 `KNOWLEDGE_GENERATIONS_ENABLED=true` 后，新查询任务才使用已发布代次；Index Worker依据任务快照消费自动结构任务，不依赖该查询开关。Embedding模型元数据、Qdrant集合与API必须一致；源文件根目录／共享卷、Redis与既有Embedding外发配置仍按原部署要求设置。

## 3. 实现分层

| 组件 | 职责 |
| --- | --- |
| KnowledgeImportService／Repository | 开始索引时锁定资料归属、明确外发授权、固定策略、创建幂等任务；不调用Embedding |
| KnowledgeIndexService | 复用原领取租约、来源读取／hash／大小／模型空间检查；按固定快照进入旧策略或自动结构策略 |
| AutomaticGenerationIndexService | 组织manifest、集合绑定、代次准备、构建、父任务续租与进度；不发布资料 |
| AutomaticGenerationRepository | 在父任务租约内绑定确定性generation_id，原子保存／校验结构并创建构建记录；不调用网络 |
| GenerationIndexService | 复用已有受治理批量Embedding、向量确认及片段进度，不另造模型通信／预算实现 |
| GenerationPublicationService／Repository | 提供认证HTTP发布／回滚与状态读取；SQL函数原子校验来源、完整性、归属及revision |

迁移026_automatic_indexing依赖025，新增任务策略快照及唯一代次绑定、不可变守卫和aegis_publish_generation函数。现有任务状态仍queued／running／succeeded／failed；processed_chunks与total_chunks反映代次实际完成量，准备阶段可以暂为0。GET任务新增index_strategy、generation_id，不返回完整index_config或标题快照。

自动任务直接从源文件构建结构代次，不先生成旧knowledge_chunks。初始原文版本可以pending，构建期间必须有同归属、有效租约的running父任务；不能把“来源未ready”泛化为其他任务的外发许可。独立代次扫描排除父任务持有的构建，避免两个入口竞抢。

## 4. 恢复与治理

每批调用前复核当前来源、外发许可及模型空间。Embedding继续使用真实generation主体的持久预算及逐次审计；标题增强文本同样计入字符额度。Qdrant确认后才记SQL片段进度，再同步到原索引任务。只有全部确认并仍获授权才ready／succeeded。

重复Redis投递不会重复领取已完成任务。异常导致failed时，通过既有retry入口重排原job；不清空预算、attempts或向量进度。进程崩溃留下running租约时，由既有SQL恢复扫描补投；新父租约领取后使旧子令牌失效，避免父租约先到期、子租约仍有效导致任务无法恢复。若子构建已ready而父状态未写入，恢复只补父状态，不重新Embedding。

向量已写入但SQL进度尚未确认时，恢复可能重复Embedding并再次计费；确定性chunk_id确保向量upsert幂等，不保证网络费用恰好一次。权限撤销、hash变化、模型／集合变化、额度耗尽仍拒绝继续；不会无界重试或换一套预算。

## 5. 发布、启用与部署

1. 在API目录评审备份后执行 `python -m alembic upgrade 026_automatic_indexing`，本次未代替用户执行。
2. 部署同版API、Index Worker、Agent Worker。先停用旧Index Worker，再开启API的structure-v1配置；旧消费者不认识新任务快照，不能混合运行。
3. 设置前述API策略和Agent的代次查询开关，启动Index Worker（`python -m aegis_agent_worker.worker.index_worker`）；日常操作不再调用结构准备CLI。
4. 上传新资料后调用原开始索引接口，轮询原GET任务。succeeded仅表示构建完成，不表示已对查询生效。
5. GET `/knowledge/documents/{document_id}/index-publication` 获取built_generation_id、version_id和revision，核对后POST同路径明确发布。
6. 调用原activation接口启用资料。未发布的自动代次返回409／KNOWLEDGE_GENERATION_NOT_PUBLISHED，即使将新任务默认策略改回paragraph-v1也不能绕过。

发布及回滚仍使用CAS revision。目标须是同归属、当前ready原文版本下validated且完整ready的代次，来源hash／标题增强／集合绑定仍一致。rollback=true可回到曾发布的ready代次，或以generation_id=null回退旧段落入口；新资料未构建旧段落索引时，回退NULL会无可检索旧片段，不自动重建。发布不修改enabled，撤权／禁用仍立即阻止检索和来源读取。

新增HTTP协议及前端待接事项按约定追加在项目根接口文档第34节。本次不修改前端。
