日期：2026-11-02。范围按用户确认收敛：先做迁移基础设施，保留旧索引，不默认启用新方案；评测通过后再做生产发布。本次完成结构影子代次准备、持久化、复核、选择与回滚控制面。**它不是完整向量重建或生产检索切换**，不把shadow validated称为业务质量通过。

## 1. 数据与隔离

新增API迁移 `023_shadow_index_generations`，依赖022。仅新增四张表与相关约束／函数／触发器，不更新任何既有文档、版本、片段、任务、向量集合或来源Artifact：

| 表 | 职责 |
| --- | --- |
| knowledge_index_generations | 每次影子重建的generation_id、来源字节hash、解析／增强配置、manifest及hash、复核记录 |
| knowledge_generation_chunks | 位置、原始结构块、标题路径、条款归属、原文范围、关系、独立检索文本及hash |
| knowledge_generation_heads | 所有者／文档／原文版本内的影子选择指针及CAS revision；NULL代表未选择，不冒充旧索引ID |
| knowledge_generation_events | 每次真实选择／回滚的原指针、目标及revision；不可改写 |

新表FORCE RLS，tenant＋user＋未删除文档所有者限制；不是租户共享发布。复合外键防止跨文档／版本／身份引用代次。manifest／片段／事件不可修改删除，已复核代次不可追加片段。历史保留不等于永久可读取，读取时仍复核当前来源权限和hash。

正文原文版本、解析版本、索引代次和标题增强配置分开；不同代次有不同chunk_id。manifest记录规范文本hash与原文件字节hash，UTF-8 BOM不会被静默混为同一个hash。

## 2. 实现及控制流程

- Worker `indexing/generation.py`：显式GenerationConfig及manifest生成；不联网。
- `repository/shadow_generation_repository.py`：事务内来源锁、请求锁、SQL持久化、复核、CAS选择／回滚和历史snapshot读取。
- `service/knowledge/shadow_generation_service.py`：请求／来源hash验证及确定性重建，不包含身份认证、文件路径选择或数据库凭据。
- `scripts/manage_shadow_generation.py`：开发环境运维入口，写操作必须显式opt-in；读取来源使用登记的storage_key和既有安全LocalDocumentStorage，不接受自定义源文件路径。

流程：当前ready来源及所有者检查 → 对request_id加事务锁 → 校验源文件字节hash → 创建prepared代次及全部片段 → 结构复核记录 → validated → 带expected revision选择影子代次 → 可回滚到之前选择过的代次或NULL。

相同用户request_id＋相同来源／配置返回原代次；复用request_id改变文档／版本／配置拒绝。新的解析／增强配置使用新的request_id，不能把它伪装成旧索引任务重试。整个准备是单一租户事务，失败整体回滚，重试不产生半套代次；未引入Redis队列、租约或新的任务预算，因为本阶段没有任何LLM／Embedding／工具请求。

validate要求调用方为可信操作程序，提交精确manifest_hash与人工／工程复核记录引用。Repository重新核对保存manifest摘要及完整片段集合，不接受“传个true就发布”。复核只证明该结构快照经记录核对，不证明向量已生成、检索质量通过或许可生产发布。该操作不开放给Agent或匿名HTTP。

select／rollback：锁文档及head，先检查revision，再验证目标同来源、同归属、validated且hash一致。过期revision失败，不自动重试；目标等于现值不重复加revision／事件。rollback至非NULL目标要求该代次曾被选择，不能任意指定新目标冒充回滚。选择不修改current_version_id，不改生产查询过滤或预算。

所有操作拒绝来源失效、删除、敏感、外发许可撤销、hash变化及不再是当前ready版本；禁用参与检索与影子结构准备是不同事项，准备不自动启用资料。历史shadow snapshot仅所有者可访问，且原版本仍有效才返回，不回退其他代次或旧Checkpoint。原生产来源读取逻辑未改变。

## 3. 部署与操作（未在业务库执行）

先备份并评审迁移，在本地开发／预发布运行API迁移，再部署带影子运维脚本的Worker代码：

```powershell
# Aegis_backend目录；此命令本次未对业务库执行
python -m alembic upgrade 023_shadow_index_generations
```

旧API／Worker不读取新表，可继续原paragraph-v1链路。迁移不自动回填所有历史向量为新代次，不接管已有Qdrant集合，不重建资料。生产检索完全不读取knowledge_generation_heads。

开发操作示例（Worker目录，替换实际UUID；这里没有替用户执行）：

```powershell
python scripts/manage_shadow_generation.py prepare --tenant <tenantUUID> --user <ownerUUID> --document <documentUUID> --version <versionUUID> --request-id structure-review-001 --allow-development-shadow-write
python scripts/manage_shadow_generation.py show --tenant <tenantUUID> --user <ownerUUID> --document <documentUUID> --version <versionUUID> --generation <generationUUID>
python scripts/manage_shadow_generation.py validate --tenant <tenantUUID> --user <ownerUUID> --document <documentUUID> --version <versionUUID> --generation <generationUUID> --manifest-hash <prepare返回hash> --validation-reference <复核记录编号> --allow-development-shadow-write
python scripts/manage_shadow_generation.py select --tenant <tenantUUID> --user <ownerUUID> --document <documentUUID> --version <versionUUID> --generation <generationUUID> --revision 0 --allow-development-shadow-write
# 回到曾经选择的代次，或不传generation清空影子指针；revision须使用当前值
python scripts/manage_shadow_generation.py rollback --tenant <tenantUUID> --user <ownerUUID> --document <documentUUID> --version <versionUUID> --revision 1 --allow-development-shadow-write
```

CLI仅允许APP_ENV=development，不是公开管理接口；tenant/user参数仅用于有数据库操作权的开发运维程序，不允许浏览器／LLM自行提供身份。输出只含代次、hash及状态，不输出源文／凭据。完整manifest由授权Repository调用读取，CLI show不把全文打印到日志。默认关闭标题增强，显式重建另一代次才使用`--title-enhancement`。

降级策略：优先保留023及数据，仅回退应用代码；不删旧代次／向量。Alembic downgrade在新表已有代次时拒绝执行，必须先导出并另行审批归档／清理，不能递归删除资料来“完成回滚”。空新表才允许降回022。指针回滚和schema降级是两件事。
