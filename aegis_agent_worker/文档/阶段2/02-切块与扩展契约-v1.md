# 3.2 切块与扩展契约 v1

日期：2026-11-02。状态：首批契约设计与独立校验实现完成，尚未接入生产索引、检索或 API。结构解析算法见3.3，数据库迁移与发布见3.5；本文不代表这些步骤完成。

## 1. 原文与身份

原文是导入后保存的规范文本快照。所有偏移使用该快照的 Python Unicode 字符半开区间 `[start,end)`，不是UTF-8字节或浏览器UTF-16位置；换行规范化必须在快照冻结之前完成。后续不得悄悄归一空白、替换换行后仍使用旧偏移／哈希。源文件字节哈希与文本／片段哈希分开。

新增内部契约位于 `src/aegis_agent_worker/indexing/contracts.py`，不替换现有 `Chunk` 或 `RetrievedEvidence`。

| 契约 | 字段及语义 |
| --- | --- |
| SourceScope | document_id、version_id、generation_id、parser_version；身份由可信代码装配，不由模型提供 |
| SourceRange | start、end，非负、非空；对应单一文本快照 |
| RawChunk | scope、structure、heading_path、clause_id、source_range、content、content_hash |
| RetrievalText | chunk_id、enhancement_version、document_title、heading_path、raw_content；确定性组装检索文本 |
| EvidenceOrigin | kind、chunk_id、trigger_chunk_id、rrf_rank；只描述来源，不授予权限 |
| EvidenceContext | 同一scope下的规范范围集合、origins、completeness与reason，不存伪造连续正文 |

`RawChunk` 检查长度等于范围长度、UTF-8 SHA-256等于原文内容哈希；`verify_source` 再核对 `source[start:end]==content`。chunk_id采用generation命名空间和完整契约确定性UUID5，同一输入稳定，不同代次不混用。完整标题路径最多6级、每级200字符；条款归属是解析器生成的稳定结构标识，不声称理解业务语义。解析器必须保留标题层级，不仅保留最近标题。

正文版本表示资料变化，parser_version表示解析规则，generation_id表示一次可切换的完整索引代次，enhancement_version表示检索文本组装规则；四者不能互相替代。算法参数及增强应用于词项／向量哪一路须绑定在代次元数据中，参数变化产生新代次。Embedding模型空间继续沿用现有profile校验，不写入原文哈希冒充正文版本。

## 2. 结构切分规则（供3.3实施）

- 先识别标题、编号条款、段落、列表、表格，再组合；只合并同章节兼容的小单元，不跨条款合并后丢失归属。未能识别的文本按段落／句子退化，不猜测例外关系。
- 超长段落优先完整句子，超长单句确定性按字符硬拆；硬拆标记 `hard_split`，不得无限放宽上限。首批原始块硬上限维持800字符，实验目标size／overlap另由策略冻结，不能宣称800字符等于某个Token数量。
- 超长条款子块共享clause_id，正文保持连续切片；重叠优先完整句子／结构单元，但不能超过上限，实际重叠由偏移证明。
- 列表保留引导句、嵌套项的关联；不能把引导句复制进每个子块后仍称原文切片。超长列表项按同样的句子／硬拆规则处理。
- 表格优先按完整行切分，过长行允许确定性硬拆并标记；表头是独立原文范围，复用表头用多范围上下文表达，不能给复制表头后的拼接正文分配虚假的连续偏移。
- 条款编号、列表引导句和表头等关系的持久化字段／表在3.3与3.5细化；现有类型能表达原文单元和多段来源，但不是已实现这些关系的自动抽取器。
- “但是／除外”等只是辅助线索；跨章节引用先保留原文和 unresolved_reference 状态，不自动扩展整章、不把相邻内容认定为全部必要条件。

## 3. 三种文本不得混淆

1. 原始证据：原文切片及其哈希，可引用。
2. 检索增强文本：`文档标题\n完整标题路径\n原文`，使用独立input_hash与title-path-v1版本；verify_chunk核对原文、路径及chunk ID。改标题增强必须重建受影响的词项／向量索引，不复用旧向量。
3. 回答上下文：授权原文范围集合，展示分隔符是排版不是原文。确定性标题可作为导航元数据，不能替代原句证明业务事实；首批不引入LLM生成增强文本。

## 4. 扩展、合并与排名

直接命中kind=direct必须有自己的rrf_rank，不带trigger；same_clause、adjacent、parent必须记录触发块，rrf_rank必须为空。parent仅为未来可表达类型，首批不自动启用父子召回。

所有扩展限制在同文档版本、同generation及parser范围，SQL以可信tenant/user检查可见性、enabled、ready和当前有效代次；引用关系、clause_id或相邻位置不是权限证明。内部 `verify_origins` 检查scope、原块范围及同条款关系；邻接距离、父子关系、触发块确为本次直接命中和SQL授权还须在3.3服务中验证，不能以Schema通过代替。

合并顺序：授权候选 → 直接命中按既有排序 → 同条款优先 → 同章节相邻按距离／原始位置稳定排序。去重时直接命中优先保留，扩展不伪造RRF分数。保留触发关系的完整诊断，不把合并后的多个块当作一个模型命中。

`merge_ranges`只合并重叠或接壤的区间，不填充中间缺口；范围集合必须按位置排序，去除重叠后保留多段。每段均来自同一scope，来源读取逐段核验后展示。交付前再次复核全部证据，撤权或代次变化使相关旧上下文失效。

## 5. 完整性与三层额度

| 层次 | 额度与约束 |
| --- | --- |
| 初始候选 | 保留现有两路各20及RRF策略作为基线；新实验可另版本配置，不全局改默认值 |
| 内部扩展 | 本版契约硬上限16个规范范围、32个去重来源；实际启用数量、邻接距离、累计读取字符／字节、耗时由3.3策略限定，不以Schema上限当默认读取量 |
| 最终交付 | 现有v1仍最多5条、每条800字符、结果12000字节；新增多段上下文暂不直接送入现有API |

内部额度不是绕过Harness或无限SQL读取的许可；范围正文必须额外计字符、序列化字节，可信Token估算缺失保持unknown，不伪报0或按字符计费。

completeness：not_assessed表示尚未评估；scope_complete仅证明已声明的结构范围在额度内完整，不证明事实正确或所有业务例外已找到；incomplete须带budget、source_unavailable或unresolved_reference原因。已知必要条件放不下时不能标scope_complete。完整性由代码事实和显式未解决项共同约束，模型不能自行认证。

保留必要条件的完整范围，放不下时不截断原文后复用哈希；进入有限补查或保守回答／不可用，记录原因。除旧v1已能独立完整表示的原块外，复合范围不能强转为单个RetrievedEvidence，不借用其中一个chunk_id掩盖其余证据。

## 6. 接入与兼容路线

本次只新增内部契约，无迁移、无API/SSE变化、无策略开关和生产行为改变。3.3先在隔离实验生成结构块与扩展结果。3.5设计代次存储、原子切换和历史来源读取；不得假设当前表已支持generation。
