# 完整记忆形成与生命周期：调研及设计依据

日期：2026-11-04。仅调查与规划，代码待实施。此前主线四召回优化代码已撤回，本文件是新的生命周期设计说明，不沿用旧实验及完成声明。

## 1. 目标校正

要完成的是：从已授权对话辨别可复用信息，形成记忆，随时间和用户纠正进行整合、更新、失效和遗忘。‘本次检索哪些已保存内容’只是读取侧。

```text
已提交消息＋用户模式／排除范围
  → 有界增量处理任务
  → 候选提取与价值／敏感性筛选
  → 与旧记忆查重、比较和变更提案
  → 用户确认或策略允许的自动批准
  → 有效记忆＋证据／版本／有效时间
  → 后续使用和纠正
  → 过期／撤销／覆盖／归档／删除清理
```

没有价值的信息可以不进入长期记忆，不必先存下来再删除；某次不用不代表已经忘记。用户要求忘记、来源失效、TTL到期与‘因为很久没用而降低保留优先级’是不同决策，必须分别表达。

## 2. 原始资料与项目取舍

| 资料 | 原方法关注点 | 项目采用／暂缓 |
| --- | --- | --- |
| [Mem0论文](https://arxiv.org/html/2504.19413v1) | 从新对话和有界上下文提取事实，与相似旧记忆比较，选择ADD／UPDATE／DELETE／NOOP | 采用分阶段形成与整合；模型仅提案，删除／覆盖由代码、授权及用户控制执行，不照搬自动DELETE |
| [LangMem提取指南](https://langchain-ai.github.io/langmem/guides/extract_semantic_memories/) | 支持结构化记忆抽取和管理，区分由应用控制存储与由Store管理器执行更新 | 借鉴Schema和提案／持久化分离，不替换现有Repository或自动授予工具写入 |
| [LangMem后台处理指南](https://langchain-ai.github.io/langmem/guides/delayed_processing/) | 延迟后台记忆处理 | 借鉴异步处理思路；持久游标、outbox、租约和取消是本项目自行补充的工程要求 |
| [Zep论文](https://arxiv.org/abs/2501.13956) | 时序知识图谱及历史关系管理 | 借鉴时间与来源意识，首批用SQL版本及有效时间实现；图数据库不是前置条件 |
| [A-MEM论文](https://arxiv.org/abs/2502.12110) | 自动生成结构化笔记、建立关联并演化记忆网络 | 原子事实与上下文值得借鉴；自主链接和历史记忆演化暂缓，避免未经审核改写用户事实 |
| [MemoryBank论文](https://arxiv.org/abs/2305.10250) | 依据时间及重要性设计遗忘与强化 | 列为软遗忘候选；首版先TTL、覆盖、撤权及用户删除，不将统一衰减直接作为永久偏好的删除规则 |

这些方法的论文指标、聊天语料和任务与Aegis不同。上述取舍是工程判断，不是已验证效果或SDK能力等价声明；先复用项目框架，不新增整套记忆平台依赖。

## 3. 首批算法选择

形成阶段：确定性来源／隐私门控＋有界结构化LLM抽取。价值不是靠关键字或模型分数单独判定，结合持久性、明确意愿、复用可能及证据支持；临时指令与永久偏好必须区分。

整合阶段：规范key／范围／指纹查重＋有界相关旧值比较。准确实体优先，必要时才引入Embedding或受限模型关系判定；返回创建、忽略、更新、替换或撤销提案。对相似但条件不同的事实不盲合并。

生效阶段：建议确认是默认模式；受控自动是用户明确开启后的限定路径。人工确认、策略自动批准与普通读取权限不混淆；用户手动值和冲突变更保留明确核对。自动形成不必等于自动永久保存所有信息。

遗忘阶段：即时有效性撤销＋异步派生副本清理；弱价值信息先不形成或产生可解释归档建议。未被召回不是负反馈，重复模型复述不是事实强化，访问量不能自动延长事实有效期。

## 4. 与现有项目衔接

已存在：MemoryService、MemoryLifecycleRepository的手动确认／冲突及版本处理；Worker的MemoryContextService、权限前置查询、来源复核和使用审计。新增的是形成任务、提案、整合与策略批准、对话证据、遗忘清理及用户控制入口；不能声称这些已经由手动管理接口提供。

现有source='user_confirmed'不能复用于自动批准；source_kind和来源版本也需在迁移设计时明确。自动事实不冒充手动录入，任务状态更新时间不替代源消息稳定版本。主对话不直接持有数据库记忆写入权，领域Agent不自行新增或覆盖记忆。

PostgreSQL负责状态、证据及权限；Redis负责唤醒，不单独保存不可恢复的形成队列。模型调用复用GuardedLLMClient／Harness，但后台memory-job主体和预算必须真实建模。Qdrant及Qwen可选用于相关旧记忆比较，不继承知识资料外发授权，也不必等到向量优化完成才跑通最小形成流程。

## 5. 可核验的产品例子

| 用户表达／事件 | 首批预期行为 |
| --- | --- |
| ‘以后回复尽量简洁’ | 形成reply_style候选，按用户模式确认或受控批准，保存来源 |
| ‘这次邮件短一点’ | 当前任务参数，不推导永久偏好 |
| ‘我是上海团队的项目协调人’ | 稳定事实候选；含糊范围可待核对，不猜项目权限 |
| ‘这周会议优先下午’ | 带时间范围的阶段事实，不覆盖永久设置 |
| ‘以后改成正式风格’且存在旧值 | 展示新旧值及替换提案，原值在变更批准前仍按原状态管理 |
| 同一消息重投／助手复述偏好 | 幂等忽略，不制造独立证据或无限强化 |
| ‘他说自己喜欢下午开会’ | 不当作当前用户偏好；第三方记忆另行设计 |
| ‘忘掉我的某个联系人’但有多项匹配 | 先澄清；不以相似度最高项直接删除 |
| 用户明确删除记忆或源对话 | 撤销使用，按派生关系取消待执行提案、清理副本，阻止旧任务重建 |
| 长期没用到的时区设置 | 不仅因未访问而删除；有效期／用户意愿才决定失效 |
