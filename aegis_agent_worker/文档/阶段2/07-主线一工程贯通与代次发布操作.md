# 主线一工程接入：代次构建、检索、复合来源与回滚

> 后续更新：[开始索引自动化与发布接口](08-开始索引自动化与发布接口.md)已接通新资料自动结构索引和HTTP发布。本文的手动prepare／validate／enqueue流程保留供历史资料显式重建与实验使用，不再是普通新资料索引的前置步骤；当前部署需迁移至026_automatic_indexing。

日期：2026-11-02。状态：此前缺失的四项工程接入已实现，隔离真实PostgreSQL＋网络替身链路验证通过。生产默认关闭，未修改业务.env、未对业务库执行迁移、未实际发布代次、未调用收费模型。**工程可通不等于算法质量验收或线上真实服务验收通过**。

## 1. 新增与兼容

迁移025_generation_runtime依赖024，新增：

- knowledge_generation_builds：独立代次任务、租约、尝试数、状态、绑定namespace／collection。
- knowledge_generation_points：远端确认写入后的片段进度；复合外键匹配generation／chunk／tenant／owner。
- knowledge_generation_publications：独立于shadow head的正式代次指针及revision。
- knowledge_generation_releases：不可修改的发布／回滚记录。
- embedding_execution_budgets.generation_id：独立真实代次主体，沿用knowledge_index用途和既有原子预算，不伪装聊天run或重复使用旧索引job。
- security_invoker视图knowledge_runtime_chunks：每个文档版本仅旧片段或已发布ready代次；knowledge_historical_chunks：保留旧／历史代次来源。两者都必须经Repository当前权限／版本过滤，不是匿名全文接口。

旧knowledge_chunks、knowledge_index_jobs、源文件、向量和Artifact不删不改。新代次独立chunk_id，不覆盖旧向量。旧模型空间／collection绑定仍由原文版本确定，新任务禁止混用不同模型空间／集合；不自动另建不受控向量集合。

## 2. 任务与检索接入

1. 现有导入与首次索引保持不变；资料原文版本ready后，开发运维显式prepare结构代次并validate，之后enqueue新代次任务。没有自动替用户发布、自动给所有历史资料重建。
2. Index Worker在代次开关开启时，扫描专用SQL队列，领取180秒租约，最多3次领取。每批续租、复核来源及外发，复用EmbeddingExecutor持久化预算；按供应商条数与INDEX_POLICY字符额度装批，标题增强文本也计入额度。
3. Qdrant确认upsert后才写points进度；崩溃后相同代次继续，已确认片段跳过，预算不重置。远端已写入但SQL未标记时可能重做Embedding并额外计费；同ID upsert幂等不意味着调用免费。旧token不能标记新租约任务完成。
4. 来源／标题（启用标题增强时）／模型空间变化拒绝继续。全部片段确认且来源仍有效才ready；failed显式retry-build，不能清零attempts或预算。评测审查与revision校验后，运维才可publish。
5. Agent新任务开关开启时固定`-g1`策略变体。旧run沿用旧策略不自动切换；新运行根依赖统一使用GenerationRetrievalRepository／GenerationQdrantSearch。关闭新任务开关不删除历史策略和来源支持。
6. SQL在召回前固定当前可访问的片段ID白名单，最多4096；超限明确拒绝。全文按该集合检索，向量同时受tenant、版本、模型空间及has_id集合限制，不先查全库再隐藏结果。指针并发切换后若当前视图不再返回旧候选，可少返回／失败，不混入新代次补位。
7. RRF融合 → SQL复核 → 可选Rerank → 最终直接命中 → SQL同代次结构快照 → 同条款优先／相关表头引导段／同章相邻扩展 → 总上下文／JSON额度 → 再次来源复核 → 回答和持久化。

新增GenerationContextService不复用会挤掉直接证据的离线裁剪协议：先保留全部已选直接命中，再试加每源最多2个独立原文parts；所有附加项计入3500字符／12000字节，放不下就不加并标context_incomplete，不能挤掉、截断或改写主命中。按chunk_id去重，连续原文切片各自保留hash；重叠片段不拼成伪造新chunk／新hash，引用范围按原始位置表达，重复部分仍计实际输入成本。不宣称已自动识别全部例外或解决跨章节引用。

## 3. 复合证据与历史读取

RetrievedEvidence新增可选generation_id、parts、context_incomplete，旧数据序列化不补默认字段。主证据保持原文，part包含chunk_id、偏移、excerpt、hash、origin、trigger_chunk_id，不伪造直接RRF排名。一个来源编号同时覆盖该主块及其经复核parts，不新增超出5个根引用编号。

出现代次证据时生成`artifact_type=knowledge_sources_v2`（外壳version仍1），payload含schema_version=2；旧knowledge_sources仍走旧协议。KnowledgeAgent能看到parts和不完整标记；指令明确不把context_incomplete当例外穷尽证明，但模型遵循质量仍须实测。

Worker EvidenceRepository复核根块及每个part的document/version/generation/hash/位置/正文。API历史ArtifactService同样逐项从SQL核对；任一part失效保守丢弃整个根来源，历史编号不重排，不回退旧摘录。发布指针回滚后，同一有效原文版本的历史代次来源仍可核对；撤权、禁用、删除、敏感或原文版本不再有效时立即不可读。

新来源GET路径见接口文档篇末，可分别读取根块和parts；旧来源GET不改义。前端本轮未修改，尚不认识knowledge_sources_v2的客户端需按篇末协议升级后才能完整展示新卡片；后端链路通过不等于旧前端已可视化。

## 4. 启动与操作顺序

1. 评审备份，在API目录执行`python -m alembic upgrade 025_generation_runtime`（本次未对业务库执行）。
2. 部署同版API、Agent Worker、Index Worker。先保持`KNOWLEDGE_GENERATIONS_ENABLED=false`验证旧入口；RERANK独立开关，不是代次链路前置条件。
3. 本地开发／预发布需要新任务时，在Agent／Index Worker配置`KNOWLEDGE_GENERATIONS_ENABLED=true`并重启；保留旧任务历史策略。CLI仍仅允许APP_ENV=development，生产运维授权入口需另经环境发布管理，不直接暴露脚本为HTTP或绕过环境限制。
4. 资料ready后在Worker目录运行原prepare／validate（详见05），可用`--title-enhancement`显式生成另一代次。validate只核对结构，不等于向量ready或质量通过。
5. 使用相同tenant／owner／document／version参数及generation执行：

```powershell
# 以下UUID须替换为实际值；没有替用户执行这些操作
python scripts/manage_shadow_generation.py enqueue --tenant <tenant> --user <owner> --document <doc> --version <version> --generation <generation> --allow-development-shadow-write
python scripts/manage_shadow_generation.py build-status --tenant <tenant> --user <owner> --document <doc> --version <version> --generation <generation>
# failed且领取未达上限时才可retry-build；不重置Embedding预算
python scripts/manage_shadow_generation.py retry-build --tenant <tenant> --user <owner> --document <doc> --version <version> --generation <generation> --allow-development-shadow-write
# ready并有评测／发布批准记录后，才显式切换；revision初始0，之后用当前revision
python scripts/manage_shadow_generation.py publish --tenant <tenant> --user <owner> --document <doc> --version <version> --generation <generation> --revision 0 --validation-reference <批准记录> --allow-development-shadow-write --allow-production-publication
# 回退旧链路：不传generation；或传之前实际发布过的ready代次
python scripts/manage_shadow_generation.py rollback-production --tenant <tenant> --user <owner> --document <doc> --version <version> --revision 1 --validation-reference <回滚记录> --allow-development-shadow-write --allow-production-publication
```

shadow select／rollback仍只操作影子指针，不能误当正式发布。正式publish同时要求显式参数、代次开关、ready完整进度、validated／来源hash／模型空间及CAS revision。批准记录是可信运维人员提供的审查依据，不声称代码可以验证自然语言评测结论真实性；Agent没有发布工具。

## 5. 回滚及部署限制

回滚优先切正式指针至NULL／历史ready代次，不删除源文、片段、Qdrant向量或预算。不得把旧API回滚到不认识v2的版本，否则历史来源无法按新契约撤权刷新；应保留兼容API和EvidenceRepository，应用回滚只关闭新任务／回退指针。运行中任务仍按原策略和已选证据复核，不重置预算。

迁移在存在build时拒绝降级；不要为通过downgrade强行清库。025数据库迁移、服务部署、运行配置和实际发布是四个独立动作，开关不能代替迁移，影子validated不能代替发布。

## 6. 验证边界

新增真实本地PostgreSQL集成用例使用随机临时schema与NOLOGIN/NOSUPERUSER/NOBYPASSRLS角色，实际执行025：结构准备→复核→入队→Embedding治理SQL→向量确认替身→ready→publish→同代次检索及扩展→ToolGateway→真实KnowledgeQueryWorkflow（答案替身）→v2 Artifact刷新→回退旧索引→历史代次仍可读→禁用后来源拒绝。事务结束确认schema／角色不存在。

向量与Embedding、答案模型均是替身；没有外网、真实费用、真实索引发布或业务数据写入。另有HTTP替身验证Qdrant has_id过滤，单测验证增强批次字符额度、旧任务不增权和直接证据不被扩展挤掉。真实模型／网络／答案质量、并发压力与失败注入仍属独立验收，不用这一工程通路宣称3.4或算法发布质量通过。

最终验证：Worker全量 **940通过／2跳过**，API全量 **181通过／40跳过**；023／024／025真实临时SQL用例另外显式运行 **3项通过**，schema／角色均回滚确认不存在。追加验证了来源hash变化、ready前禁止发布、旧revision拒绝、私有／租户共享读取以及禁用失效。API首次回归暴露旧测试传入未带artifact_type的v1数据时新分支KeyError，已改为兼容读取；未通过删减旧测试掩盖问题。仅有既有LangGraph弃用警告。
