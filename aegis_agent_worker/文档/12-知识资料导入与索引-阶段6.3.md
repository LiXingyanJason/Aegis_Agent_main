# 知识资料导入、切块与索引（6.3）

后续6.4已接入真实Hybrid代码，默认不开启，尚未进行云端联调；见[6.4配置与验收](13-权限前置Hybrid检索与RRF-阶段6.4.md)。本页记录6.3边界与测试。

## 1. 范围与状态

已实现三个独立操作：上传保存、显式启动索引、显式启用／禁用。支持Markdown/TXT或直接文本、本机源文件存储、独立Index Worker、
确定性切块/中文检索文本、受治理Embedding、Qdrant幂等写入与SQL完成状态。
完整版本管理、已有文档更新、PDF/Word解析及下载/URL导入尚未实现；6.4检索已由后续步骤实现。
知识查询开关仍建议关闭；索引成功不等于聊天已经能够查询这些资料。

本次测试不调用真实阿里云/Qdrant，也没有升级当前业务库。云读写联调需用户启动索引进程后完成。

## 2. 文件与调用关系

```text
API knowledge_controller → KnowledgeImportService
  → LocalDocumentStorage（不可变UUID对象，开发源文件）
  → KnowledgeImportRepository（版本/上传幂等，enabled=false；不创建job）

POST /knowledge/documents/{document_id}/index-jobs（显式外发授权）
  → 核验所有者/敏感标记/Embedding配置 → 创建或复用job
  → 事务提交后 KnowledgeDispatchService → Redis专用List

worker/index_worker.py（独立进程）
  → KnowledgeIndexRepository：领取租约 / 过期回收
  → KnowledgeIndexService
     → DocumentStorage读文件/hash校验
     → indexing/chunker.py（段落切块/字符位置/中文字和二元词组）
     → EmbeddingExecutor（持久化预算/超时/审计）→ EmbeddingClient
     → vector/QdrantVectorIndex（wait=true确认）
     → SQL批次进度 → 全部完成才ready及首次绑定current_version_id

PATCH /knowledge/documents/{document_id}/activation
  → 所有者显式启用ready资料／禁用资料 → 只更新SQL enabled，不投递任务
```

API/Worker不互相导入应用代码；两侧保留小型同契约LocalDocumentStorage实现并共享根目录。
后续可分别换成OSS适配，不影响Agent契约。数据库保留片段文本，Qdrant只存向量和引用/过滤元数据。
源文件key由服务器生成，不使用原始文件名作路径；源文件根目录必须仅允许受信进程写入。

## 3. 迁移与配置

新增 `012_knowledge_indexing` 和 `013_knowledge_lifecycle`，不改写010～012；012与已移除的pgvector迁移不是同一个revision。
迁移增加外置源文件引用、幂等请求、租约、索引进度、解析版本、向量空间绑定及批次确认时间。
旧source_text仍可读取，新导入不在SQL重复保存整份原文。
降级时若有source_text=NULL外置文件版本会明确拒绝，需先恢复内联文本并备份，不能stamp绕过。

在Aegis_backend先执行：

```powershell
D:\anaconda\envs\Aegis\python.exe -m alembic upgrade head
D:\anaconda\envs\Aegis\python.exe -m alembic current
```

期望 `013_knowledge_lifecycle (head)`。迁移先于新版API／Worker，并停止旧查询代码后升级。
013把上传幂等凭据迁至文档、使未索引版本的模型空间字段可空、增加enabled默认false。
旧资料也默认禁用，已完成索引保留、已有排队任务仍可处理；不会自动启用或重新生成向量。
升级后需所有者手动启用已ready资料。013降级遇到未配置模型空间的上传资料会拒绝；
降级会移除启用标记和新增上传幂等字段，先备份并停止查询，不能stamp绕过。

API和Worker的实际.env都添加以下元数据（以你的Worker真实配置为准）：

```dotenv
KNOWLEDGE_STORAGE_ROOT=D:/AI/Aegis_Agent_main/data/knowledge-sources
KNOWLEDGE_MAX_SOURCE_BYTES=262144
KNOWLEDGE_INDEX_QUEUE_NAME=aegis:knowledge-index-jobs
KNOWLEDGE_INDEX_MAX_CLAIMS=3
EMBEDDING_PROVIDER=openai_compatible
EMBEDDING_MODEL=text-embedding-v4
EMBEDDING_MODEL_VERSION=text-embedding-v4-profile-v1
EMBEDDING_DIMENSIONS=1024
```

仅上传不需要Embedding配置；启动索引时API需要上述模型元数据，但不需要Embedding密钥。
Worker保留独立Embedding/Qdrant实际配置，并添加EMBEDDING_MAX_BATCH_ITEMS=10。
不修改已发布的embedding-index-v1（仍为16条上限）；治理和客户端额外限制供应商批量，索引按最多10条拆分。
每片段至多700字符，重叠80字符，最大512片段；首期默认256KiB源文件，请求体额外允许64KiB封装。
文件和实际请求体都限大小，不依赖客户端Content-Length；目前仅接受非空UTF-8纯文本，无NUL字节。

API/Worker异机运行需共享卷或后续OSS；不能依赖相同字符串的本机路径就认为数据共享。
启动API及独立索引进程：

```powershell
# 在aegis_agent_worker目录
D:\anaconda\envs\Aegis\python.exe -m aegis_agent_worker.worker.index_worker
```

Agent聊天进程可另开终端运行，两个进程使用不同队列。
Index Worker的恢复扫描需要跨租户索引任务调度权限；当前开发使用已有维护连接。
业务内容读写回到tenant_transaction并显式核验所有者。生产应配置专用最小权限调度角色，
不能把超级用户凭据给客户端/API，也不能宣称现有超级用户连接受RLS保护。

## 4. 幂等、恢复与安全边界

- client_request_id按tenant/user隔离。相同内容/元数据重放返回原文档/job；不同载荷返回409。
  使用事务级请求锁及唯一索引，并不提供跨文档内容去重或多版本更新。
- Redis仅携带job_id/身份UUID封包；归属必须与SQL事实一致，不能携带源文件、路径、向量或模型指令。
- SQL任务领取使用token/过期时间/CAS。重复消息不会并发执行，同一job崩溃后过期可重领。
- 30秒周期扫描补投（Redis失败/进程崩溃均可恢复），默认最多3次领取，队列达到1000条时暂缓补投。
  正常耗时长于租约时旧token不能完成新领取任务。每个批次前续租，不无限重试网络请求。
- 批次写入wait=true且确认completed后才记录indexed_at；已确认片段在重试时跳过。
  Embedding完成但尚未确认写入时崩溃，重试可能再次调用模型；预算不会退还或重置，不承诺恰好一次计费。
- 点ID由内容/位置/解析版本确定，重试upsert不产生重复点。未确认任务绝不标ready。
- 上传只做本地保存，允许external_embedding_allowed=false或is_sensitive=true，不执行外发。
  启动索引必须在请求中显式external_embedding_allowed=true且资料is_sensitive=false；
  上传时勾选外发授权不代替这次启动授权，也不会自动排队。
  Worker每批次再核验文件hash、模型空间、资料状态/外发授权；文档内容不能成为工具指令。
- collection不存在时任务初始化创建为实际维度/Cosine；已有维度不符直接拒绝。
  SQL固定endpoint+collection对应模型空间；未绑定且非空集合不自动接管，不删除/重建已有集合。
- 新写入的向量payload不包含正文，只含租户/所有者、文档/片段/版本引用、hash、范围及模型空间；旧向量的历史类别字段不参与查询。
  payload权限可能滞后，6.4检索仍必须以SQL做最终核验。
- ready表示索引完整，不表示资料已启用。启用必须由所有者操作且索引完整、非敏感、仍获外发授权。
  禁用立即阻止新的证据读取，不删除文件／片段／向量，不取消正在执行的索引。
  6.4两路检索都必须先过滤enabled，再做SQL权限复核；不能撤回已展示的答案。
- failed任务仅所有者可显式retry，同一job预算和已确认批次不清零；领取次数上限或Embedding预算耗尽会拒绝继续。
  参数/配置错误修复后可在上限内重试；超过上限需要后续显式重建能力，本版不偷偷新建任务重置预算。

## 5. 文件失败补偿

源文件登记SQL失败时删除本次已落盘的独立对象；最终事务提交失败也可能留下孤立文件。
提供显式清理工具，默认dry-run，最多核验100个至少24小时前的UUID对象，SQL仍有任何版本引用就不删除：

```powershell
# Worker目录；仅具备全租户引用读取权限的维护连接
python scripts/cleanup_knowledge_orphans.py
# 确认统计和备份后，显式执行（删除不可恢复，谨慎）
python scripts/cleanup_knowledge_orphans.py --apply
```

本次没有运行实际文件删除。有效源文件、非UUID文件及符号链接不属于清理范围。
SQL中隐藏/删除状态不等于无引用，清理不会因用户级RLS看不到文件就误删别人的资料。
删除/撤权仍以SQL立即阻止访问；本阶段不开放资料删除/失效/下载接口或多版本产品功能。
