# 路由审计与模型用量可观测性（阶段 4.5）

本阶段只记录决策与用量，不选择模型、不估算金额，也不改变字符预算、权限或审批。

## 1. 实现位置

| 组件 | 职责 |
| --- | --- |
| `MainDecisionWorkflow` | 汇总候选、筛选原因、修复次数、校验错误类型及安全兜底原因 |
| `DecisionContextService` | 将 `main_decision_completed` 写入事件表，提交后发布现有 SSE |
| `MainAgent` | 通过协程上下文标记 `main_routing` 或 `main_routing_repair`；不新增模型调用 |
| `llm/usage.py` | 解析可选 Token 计数，管理代码白名单用途标签 |
| `OpenAICompatibleClient` | 保持 `complete/complete_json -> str`，解析响应中的 `usage`；使用 ContextVar 隔离并发调用 |
| `GuardedLLMClient` | 将本次用量与用途交给已有 Harness 审计；异常时也尝试保留已报告用量 |
| `HarnessExecutor` / `ExecutionRepository` | 每次模型调用仍占用一次预算，结束时更新对应的 `run_execution_attempts` 行 |

所有生产模型调用仍经过 GuardedLLMClient。直接调用裸模型客户端只解析用量，不自动持久化。

## 2. 安全路由事件

现有事件保留目录版本、结果、模型信息、耗时及决策摘要，新增／复用：

- `route_policy_version`、`candidate_capabilities`、`filter_reason_codes`；
- `repair_count`、`validation_issue_codes`（只有字段路径和错误类型）；
- `fallback_reason`：正常校验成功为 `null`，受控澄清／失败时为稳定结果代码，如 `invalid_output`、`invalid_target`、`model_failed`。

不写入用户任务全文、澄清问题正文、完整卡片／邮件正文、原始模型响应或思维过程。
`fallback_reason` 仅描述现有处理结果，不表示新增自动执行兜底。
主 Agent 明确选择澄清不一定是错误；若处理结果为 `validated`，此字段仍为 `null`。

## 3. 逐次用量

新增可空列：`purpose`、`model_provider`、`model_name`、`prompt_tokens`、`completion_tokens`、`total_tokens`。

用途为代码白名单：主路由首次请求 `main_routing`，格式修复 `main_routing_repair`；
其他调用暂用 `model_json` 或 `model_completion`，不是让模型自报用途。
卡片读取后的下一轮主决策仍是一次 `main_routing`，不是格式修复。

每次请求单独一行，包括失败请求。业务 Schema 不通过但 HTTP 返回文本时，模型通信尝试可以是
`succeeded`；是否进行修复由路由事件记录。HTTP 内容缺失或为空则尝试失败，已报告用量仍保留。
超时／网络失败没有用量时保存 `NULL`。工具行的这些模型字段也为 `NULL`。

只接受供应商返回的非负整数（包括真实的 0）；缺失、负数、布尔值、字符串、浮点数或超过 BIGINT
范围的计数均为 `NULL`。不根据字符数估算 Token，也不从两个字段自行推算第三个字段。
历史记录保持 `NULL`，不能用 `COALESCE(tokens, 0)` 宣称统计完整。

示例统计（同样遵循现有租户权限，不新增公开统计接口）：

```sql
SELECT purpose,
       count(*) AS attempts,
       count(total_tokens) AS reported_attempts,
       count(*) - count(total_tokens) AS unknown_attempts,
       sum(prompt_tokens) AS reported_prompt_tokens,
       sum(completion_tokens) AS reported_completion_tokens,
       sum(total_tokens) AS reported_total_tokens
FROM run_execution_attempts
WHERE run_id = :run_id AND kind = 'model'
GROUP BY purpose;
```

这些是供应商报告的用量，不是计费账单。没有增加供应商单价、金额换算或多模型路由。

## 4. 迁移与发布顺序

新增主后端迁移 `009_model_usage_audit`，依赖 `008_agent_harness`，仅增加可空列和非负约束，
不修改 RLS 或已有行。**不要直接启动新版 Worker 后再补迁移，否则审计更新会因缺列失败。**

推荐顺序：停止旧 Worker → 备份并执行迁移 → 发布新版 Worker → 启动并验证。
迁移由主后端维护，API 版本需携带此迁移文件；现有 API 运行代码和前端协议无必需改动，
旧 API／旧 Worker 可兼容新增可空列，新 Worker 需要数据库至少到此版本。

在 `D:\AI\Aegis_Agent_main\Aegis_backend` 执行：

```powershell
D:\anaconda\envs\Aegis\python.exe -m alembic current
D:\anaconda\envs\Aegis\python.exe -m alembic upgrade head
```

不使用 `stamp` 跳过结构变更。降级前先停新版 Worker、恢复旧版代码；降级会删除新增审计列，
丢失其中的用量数据，应先备份。普通代码回滚不需要立即降级数据库。
